## Зачем прерывания

Прерывание — сигнал, по которому процессор приостанавливает текущую программу, выполняет специальную подпрограмму — обработчик (ISR), а потом возвращается точно туда, где остановился. Альтернатива — опрос (polling): процессор в цикле спрашивает устройство «готово?». Опрос тратит время впустую, когда событий нет; прерывание будит процессор только тогда, когда устройству действительно есть что сказать (нажата клавиша, пришёл пакет, диск дочитал блок).

! Вопрос УМКД: **Что такое прерывание процессора?** — Прерывание — сигнал, по которому процессор приостанавливает программу и выполняет обработчик, затем возвращается.

## Виды прерываний
| Вид | Кто вызывает | Примеры |
| Аппаратные внешние | устройства через линии IRQ контроллера — в любой момент (асинхронно) | таймер (IRQ0), клавиатура (IRQ1), диск, сеть |
| — маскируемые | можно запретить: флаг IF (команда CLI) или маска в контроллере | все IRQ |
| — немаскируемое NMI | запретить нельзя, вектор 2 | ошибка памяти (чётность), сбой питания |
| Программные | команда INT n в программе | INT 21h — функции DOS, INT 10h — видео BIOS, INT 80h — Linux |
| Исключения (внутренние) | сам процессор при выполнении команды (синхронно) | деление на 0 (вектор 0), неверный код операции (6), ошибка страницы (14), общая защита (13) |

Исключения бывают: fault (после обработки команда повторяется — ошибка страницы), trap (продолжение со следующей — точка останова INT 3), abort (продолжить нельзя — двойная ошибка).

Запрет прерываний называется маскированием (это вопрос из базы).

! Вопрос УМКД: **Чем аппаратное прерывание отличается от программного?** — Аппаратное vs программное: от устройства через IRQ против команды INT n в программе.
! Вопрос УМКД: **Что такое маскируемое прерывание?** — Маскируемое — его можно запретить (флаг IF, маска контроллера).
! Вопрос УМКД: **Что такое немаскируемое прерывание?** — Немаскируемое (NMI) — запретить нельзя; критические события (ошибка памяти, питание).
! Вопрос УМКД: **Чем исключение процессора отличается от внешнего аппаратного прерывания?** — Исключение vs внешнее прерывание: возникает внутри процессора при выполнении команды, синхронно с программой.

## Таблица векторов

В реальном режиме x86 первые 1024 байта памяти (00000h–003FFh) — таблица векторов прерываний: 256 векторов по 4 байта. Вектор — это адрес обработчика: 2 байта смещения (IP) и 2 байта сегмента (CS). Вектор номер N лежит по адресу N × 4: INT 21h → 84h, INT 09h (клавиатура) → 24h. В защищённом режиме вместо неё — IDT (таблица дескрипторов прерываний), её адрес в регистре IDTR.

## Что делает процессор при прерывании
Заканчивает текущую команду (прерывания принимаются между командами).
Если прерывание маскируемое — проверяет флаг IF; узнаёт номер вектора (от контроллера по шине данных — цикл INTA, или из команды INT).
Кладёт в стек FLAGS, CS и IP (состояние прерванной программы — поэтому в тестах «для запоминания состояния прерванной программы используется стек»).
Сбрасывает IF и TF (чтобы не прерваться ещё раз сразу).
Загружает CS:IP из таблицы векторов → выполняется обработчик. Он сохраняет регистры, которые портит, работает с устройством и посылает контроллеру EOI (OUT 20h, 20h).
Команда IRET восстанавливает IP, CS, FLAGS — программа продолжается.

! Вопрос УМКД: **Какие основные действия выполняет процессор при обработке прерывания?** — Действия процессора: закончить команду → сохранить FLAGS, CS, IP в стеке → сбросить IF → взять вектор → обработчик → IRET.

## Приоритет и арбитраж: контроллер 8259

Если несколько устройств просят одновременно, кто-то должен решить, кого обслужить первым — это арбитраж. В IBM PC его делает программируемый контроллер прерываний 8259A (PIC): 8 входов IRQ0–IRQ7; два контроллера каскадом (ведомый на IRQ2 ведущего) дают IRQ0–IRQ15. По умолчанию — фиксированный приоритет: чем меньше номер, тем выше приоритет. IRQ0 — системный таймер (наивысший), IRQ1 — клавиатура, IRQ3/4 — COM2/COM1, IRQ6 — дисковод, IRQ7 — LPT1, IRQ8 — часы, IRQ12 — мышь PS/2, IRQ14/15 — IDE. Внутри у 8259 регистры IRR (кто просит), ISR (кто обслуживается), IMR (маска).

Приоритет решается тем же приоритетным шифратором, что в теме 5: на выход идёт номер старшего запроса. Пока обслуживается IRQ3, контроллер пропустит только IRQ0–IRQ2 (если обработчик разрешил прерывания STI) — это вложенные прерывания. Другие схемы: циклический приоритет (обслуженный становится последним), опрос по цепочке (daisy chain — приоритет по физическому месту в цепи).

APIC (Advanced PIC) — в многоядерных системах: Local APIC в каждом ядре и I/O APIC на чипсете, 24+ линий, распределение прерываний между ядрами. Сейчас устройства PCIe чаще шлют прерывания сообщениями — MSI/MSI-X.

! Вопрос УМКД: **Что означает арбитраж запросов прерываний?** — Арбитраж — выбор одного запроса из нескольких одновременных (контроллер прерываний).

## Задания СРО по УМКД
Задание: Изучить классификацию аппаратных и программных прерываний. Разработать блок-схему обработки прерывания центральным процессором. Рассмотреть механизмы маскирования и приоритетного обслуживания прерываний. Смоделировать ситуацию одновременного поступления трёх запросов с различными приоритетами и определить порядок их обработки. Исследовать назначение контроллеров прерываний PIC и APIC. Объяснить преимущества использования прерываний по сравнению с постоянным опросом устройств.
Форма отчётности: Блок-схема, таблица приоритетов и аналитический отчёт.

## Разбор заданий СРО (тема 15)
**Блок-схема обработки прерывания процессором** (по шагам):
- устройство выставляет запрос (IRQ) контроллеру прерываний; контроллер выбирает запрос с наивысшим приоритетом и сообщает процессору (INTR);
- процессор заканчивает текущую команду и проверяет флаг IF: если прерывания замаскированы (IF = 0), маскируемый запрос ждёт; немаскируемое NMI обслуживается всегда;
- процессор получает номер (вектор) прерывания;
- сохраняет в стеке состояние: регистр флагов, CS и IP (адрес возврата), сбрасывает IF;
- берёт из таблицы векторов адрес обработчика (вектор = 4 байта, таблица 256 × 4 = 1 КБ в начале памяти) и переходит на него;
- обработчик сохраняет нужные регистры, обслуживает устройство, сообщает контроллеру «конец прерывания» (EOI);
- команда IRET восстанавливает IP, CS и флаги из стека — прерванная программа продолжает работу с того же места.
**Одновременные запросы с разными приоритетами.** У контроллера 8259: IRQ0 — высший приоритет, IRQ7 — низший; второй (ведомый) контроллер с IRQ8–15 подключён ко входу IRQ2, поэтому полный порядок: 0, 1, 8–15, 3–7.
Пример: одновременно пришли IRQ14 (жёсткий диск), IRQ1 (клавиатура) и IRQ8 (часы реального времени).
| Порядок | Запрос | Почему |
| 1 | IRQ1 — клавиатура | самый высокий приоритет из трёх |
| 2 | IRQ8 — часы RTC | ведомый контроллер стоит на месте IRQ2, выше IRQ3–7 |
| 3 | IRQ14 — диск | ведомый контроллер, приоритет ниже IRQ8 |
Если во время обслуживания низкоприоритетного запроса придёт более важный, контроллер может прервать обработчик (вложенные прерывания); менее важный подождёт.
**Маскирование.** Флаг IF = 0 (команда CLI) запрещает все маскируемые прерывания, STI — разрешает; маска контроллера (регистр IMR) отключает отдельные линии IRQ.
**PIC и APIC.** PIC (8259) — 8 линий, каскадом из двух — 15 запросов, одноядерные ПК. APIC (Advanced PIC) — у каждого ядра свой локальный APIC плюс I/O APIC для устройств: больше линий, распределение прерываний между ядрами, межпроцессорные прерывания.
**Прерывания против опроса.** При опросе (polling) процессор постоянно проверяет устройства, даже когда им нечего сказать, — тратит время. С прерываниями процессор занят своей работой, а устройство само сообщает о событии, и реакция быстрее.

! Вопрос УМКД: **Как определяется порядок обработки запросов с разными приоритетами?** — Порядок при разных приоритетах — сначала более приоритетный (в 8259 — меньший номер IRQ).
! Вопрос УМКД: **Почему обработка прерываний может быть эффективнее постоянного опроса устройств?** — Прерывания эффективнее опроса: процессор не тратит время на проверку неактивных устройств и реагирует сразу.
