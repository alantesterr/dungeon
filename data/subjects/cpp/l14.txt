## 🐣 С нуля — для тех, кто не знает ООП
**Проблема.** Если поле открыто (`public int age;`), любой может написать `p.age = -5;` — и программа поверит. Поэтому поле прячут (`private`), а доступ дают через две маленькие функции:
- **getter** («получатель») — отдаёт значение: `int getAge() { return age; }`
- **setter** («установщик») — записывает, но **с проверкой**: `void setAge(int a) { if (a >= 0 && a <= 120) age = a; }`
Снаружи пишут `p.setAge(20); cout << p.getAge();` — и испортить данные нельзя. Это инкапсуляция на практике.
**В C++Builder есть удобное слово `__property`** — свойство, которое выглядит как поле, но работает через функции:
```
class TTemp {
private:
  double FCelsius;
  void SetCelsius(double v) { if (v > -273) FCelsius = v; }
public:
  __property double Celsius = { read = FCelsius, write = SetCelsius };
};
TTemp t; t.Celsius = 25;     // на самом деле вызовется SetCelsius(25)
```
Без `write` свойство будет «только для чтения». Так устроены все свойства компонентов: `Button1->Caption = "OK"` — это тоже __property.

**Основные пункты:** понятие свойства; инкапсуляция данных класса; закрытые поля; методы доступа get и set; чтение и изменение свойств; проверка значений свойств; доступ public, private, protected; разделение интерфейса и реализации класса; создание свойств в C++Builder; работа со свойствами в Object Inspector; программный доступ к свойствам; проектирование класса с набором свойств.
! Дополнение: свойство, get и set
**Свойство** — характеристика объекта (переменная некоторого типа), описывающая его внутреннее состояние: возраст, цвет, ширина. Хорошая практика — хранить её в закрытом поле, а читать и менять через методы.
```
class Person
{
private:
  int age;                                  // данные спрятаны
public:
  int getAge() const { return age; }        // getter — чтение
  void setAge(int a)                        // setter — изменение с проверкой
  {
    if (a >= 0 && a <= 150) age = a;
    else cout << "Неверный возраст" << endl;
  }
};
```
- **Зачем инкапсулировать:** нельзя записать неверное значение (возраст −5), можно менять внутреннее устройство класса, не трогая код, который его использует.
- **Getter** возвращает значение поля; **setter** принимает новое и проверяет его.
- Свойство «только для чтения» — есть getter, нет setter.
- **Public-поле** можно изменить как угодно; **инкапсулированное свойство** — только через проверку.
- **Интерфейс и реализация:** объявление класса (что он умеет — в .h) отдельно от определения методов (как — в .cpp).
! Дополнение: свойства в C++Builder: __property
```
class TPerson
{
private:
  int FAge;                                 // поле (в VCL принято начинать с F)
  void SetAge(int v) { if (v >= 0) FAge = v; }
public:
  __property int Age = { read = FAge, write = SetAge };
};
TPerson p;
p.Age = 20;        // на самом деле вызывается SetAge(20)
cout << p.Age;     // читается FAge
```
Снаружи свойство выглядит как обычное поле, а внутри read и write указывают поле или метод. Без write — свойство только для чтения. Если свойство объявить в секции `__published` у компонента, оно появляется в **Object Inspector** (тема 15). Все свойства компонентов (Caption, Width, Color…) устроены именно так: `Form1->Width = 300;` вызывает метод, который перерисовывает форму.
! Дополнение: для теста на английском
Своё свойство в C++Builder объявляют ключевым словом **__property**: оно даёт чтение и запись закрытого (private) поля через read/write, например `__property int Age = {read = FAge, write = SetAge};`

## Конспект по вопросам УМКД
Коротко по каждому вопросу УМКД — на эти разделы ссылаются тесты.

## Что такое свойство класса?
**Ответ из УМКД:** Характеристика (атрибут) объекта, описывающая его состояние; хранится в поле и обычно читается/изменяется через методы доступа.
Свойство — характеристика объекта (возраст, ширина). Хранится в поле, а читают и меняют его через методы доступа.

## Почему данные класса обычно инкапсулируют?
**Ответ из УМКД:** Чтобы защитить их от неверных значений и случайных изменений и иметь возможность менять реализацию без изменения внешнего кода.
Данные прячут (private), чтобы защитить от неверных значений (возраст −5) и случайных изменений, и чтобы можно было менять устройство класса, не трогая внешний код.

## Что такое getter и setter?
**Ответ из УМКД:** Методы доступа: getter возвращает значение поля, setter записывает новое значение (с проверкой).
Getter возвращает значение поля, setter записывает новое (с проверкой): `int getAge()`, `void setAge(int a)`.

## Назначение getter?
**Ответ из УМКД:** Дать возможность прочитать значение закрытого поля.
Getter — прочитать закрытое поле.

## Назначение setter?
**Ответ из УМКД:** Дать возможность изменить закрытое поле контролируемо — с проверкой допустимости значения.
Setter — изменить закрытое поле контролируемо.

## Как setter проверяет данные?
**Ответ из УМКД:** Сравнивает новое значение с допустимым диапазоном и записывает его только если оно верное, иначе сообщает об ошибке.
```
void setAge(int a) { if (a >= 18 && a <= 65) age = a; else cout << "Ошибка"; }
```

## Разница между public-полем и инкапсулированным свойством?
**Ответ из УМКД:** Public-поле можно изменить любым значением напрямую; инкапсулированное — только через методы, которые проверяют значение.
Public-поле можно испортить любым значением напрямую; инкапсулированное — меняется только через проверяющие методы.

## Как реализуются свойства в пользовательском классе?
**Ответ из УМКД:** Private-поле + public get/set методы; в C++Builder —
__property тип Имя = {read = …, write = …};
Private-поле + public get/set. В C++Builder есть расширение `__property`:
```
private: double FCelsius; void SetCelsius(double v);
public:  __property double Celsius = { read = FCelsius, write = SetCelsius };
```

## Как обращаться к свойствам извне класса?
**Ответ из УМКД:** Через вызов методов
obj.getAge()
,
obj.setAge(20)
или, для __property, как к полю:
obj.Age = 20
.
Снаружи: `obj.getAge()`, `obj.setAge(20)`; у `__property` — как к полю: `t.Celsius = 25;` (вызовется SetCelsius).

## Преимущества свойств и инкапсуляции?
**Ответ из УМКД:** Корректность данных, защита, скрытие реализации, простота изменения класса, возможность свойств только для чтения.
Плюсы: верные данные, защита, скрытая реализация, свойства «только для чтения» (без write).

{
