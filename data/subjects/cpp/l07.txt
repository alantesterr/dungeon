## 🐣 С нуля — для тех, кто не знает ООП
**Зачем вообще ООП.** Раньше (темы 1–6) программа была кучей переменных и функций отдельно: переменная `x` тут, функция `sum()` там. Когда программа большая, в этом легко запутаться. ООП (объектно-ориентированное программирование) предлагает складывать данные и действия над ними **в одну «коробку»**.
**Класс — это чертёж.** Представь чертёж собаки: у каждой собаки есть кличка и порода (это **свойства**, или поля), и каждая умеет лаять (это **метод** — действие). Сам чертёж не лает — это только описание.
**Объект — это настоящая вещь по чертежу.** По одному чертежу можно «построить» сколько угодно собак: Шарик, Бобик… Каждая — **объект** (экземпляр класса) со своими значениями свойств.
```
class Dog {              // чертёж
public:
  string name;           // свойство (поле)
  void bark() { cout << name << ": Гав!"; }   // метод (действие)
};
Dog a; a.name = "Шарик"; a.bark();   // объект и вызов метода
```
**Событие** — «что-то случилось» (нажали кнопку, нажали клавишу). **Обработчик события** — твоя функция, которая на это отвечает.
**Четыре главных слова ООП** (их любят спрашивать в тестах):
- **Инкапсуляция** — «положить в капсулу»: данные и код вместе в классе, а лишнее спрятано от чужих рук (private). Как телевизор: кнопки снаружи, микросхемы внутри.
- **Наследование** — новый класс берёт всё у старого и добавляет своё: «Пудель — это Собака, но ещё и кудрявый».
- **Полиморфизм** — «много форм»: одно имя действия, а делает каждый по-своему. Команда «издай звук»: собака гавкает, кошка мяукает.
- **Абстракция** — берём только важное. В программе про собак нам нужна кличка, а не количество шерстинок.
**Шпаргалка:** класс = чертёж; объект = вещь по чертежу; свойство = «какой»; метод = «что умеет»; событие = «что случилось».

## Процедурный и объектный подход
! Дополнение: ООП
**Объектно-ориентированное программирование (ООП)** — подход, при котором программа строится из **объектов**, а каждый объект объединяет **данные** (что он знает) и **методы** (что он умеет).
|  | Процедурный подход (темы 1–6) | ООП (темы 7–15) |
| Основа | функции и последовательность действий | объекты и их взаимодействие |
| Данные | отдельно от функций, часто глобальные | внутри объекта, защищены |
| Пример | `double area(double w, double h)` | `Rect r(3,4); r.area();` |
| Для больших программ | трудно сопровождать | проще расширять и переиспользовать |

## Класс, объект, атрибут, метод
! Дополнение: основные понятия
- **Класс (class)** — набор данных и методов для работы с этими данными; «чертёж» (blueprint) для создания объектов с одинаковыми свойствами и поведением. Сам класс — это описание, объектов ещё нет.
- **Объект (object)** — экземпляр (instance) класса в памяти. По одному классу можно создать сколько угодно объектов: класс Dog → объекты rex, buddy.
- **Атрибут / поле / свойство** — переменная внутри класса, описывает **состояние** объекта (имя, порода, возраст).
- **Метод** — функция класса, описывает **поведение** объекта — действие, которое объект умеет выполнять (bark(), walk()).
- **Состояние** объекта — текущие значения его полей; **поведение** — набор его методов.
```
class Dog                     // класс — чертёж
{
public:
  string name, breed;         // атрибуты (состояние)
  void bark()                 // метод (поведение)
  { cout << name << ": Woof!" << endl; }
};
Dog rex;                      // объект — экземпляр класса
rex.name = "Rex"; rex.bark();
```

## Четыре принципа ООП
! Дополнение: принципы
- **Инкапсуляция (encapsulation)** — объединение данных и кода, который с ними работает, в одном объекте и **защита данных** от произвольного доступа извне. Детали реализации скрыты (private), наружу открыт только нужный интерфейс (public методы get/set).
- **Наследование (inheritance)** — механизм, при котором объект производного (дочернего) класса получает свойства и поведение базового (родительского) класса и может добавить свои. Poodle наследует Dog.
- **Полиморфизм (polymorphism)** — «один интерфейс — много реализаций»: одинаковые имена методов для разных действий. make_sound() у собаки лает, у кошки мяукает. Нужный метод выбирается для конкретного объекта.
- **Абстракция (abstraction)** — модель реального предмета, в которой оставлено только важное для задачи. Для библиотеки у книги важны название и автор, а цвет обложки — нет.
**Инкапсуляция и абстракция — в чём разница:** абстракция решает, **что** показать (какие свойства и действия есть у модели); инкапсуляция — **как спрятать** всё остальное и защитить данные.
**Преимущества ООП:** программа ближе к реальному миру; код переиспользуется через наследование; данные защищены; легко расширять (новый класс-наследник), командная разработка. **Где применяется:** программы с окнами (C++Builder: форма, кнопки — это объекты), игры, базы данных, моделирование.

**Методы Show и Hide** есть у класса **TControl** (от него происходят все визуальные компоненты): `Button1->Hide();` делает элемент невидимым (Visible = false), `Button1->Show();` — видимым (Visible = true).

## Из учебника МГУ «Основы ООП. Язык C++» (Волкова, Иванов, Карпов)

**Четыре парадигмы программирования:**
1. **Процессно-ориентированная** (процедурная, императивная) — программа есть последовательность операций, **код воздействует на данные** (модель фон Неймана). Языки C, Pascal.
2. **Объектно-ориентированная** — программа есть набор **объектов**, которые общаются через **интерфейсы**; **данные управляют доступом к коду**.
3. **Аппликативная (функциональная)** — программа есть функция y = f(x), собранная из простых функций. LISP, ML; применяют в системах искусственного интеллекта.
4. **Логическая** (система правил) — список пар «разрешающее условие → действие», условия проверяются по кругу. PROLOG.
Центральная идея ООП — **абстракция**: сложную сущность рассматривают как единое целое, не вдаваясь во внутреннее устройство. Главный способ строить абстракции — **иерархическая классификация**: сложную систему делят на более простые части. Различают **структуру классов** (типовая иерархия) и **структуру объектов** (структурная иерархия).
- **Инкапсуляция** — связывает код и данные, которыми он управляет, и защищает их от произвольного доступа извне; доступ идёт через интерфейс. Основа инкапсуляции — **класс**.
- **Наследование** — объект производного класса получает свойства родительского (базового) класса и добавляет только то, что делает его особенным.
- **Полиморфизм** — «**один интерфейс — много методов**»: например, одна подпрограмма для стеков целых, вещественных чисел и символов. Бывает **статический** (при компиляции: перегрузка функций и операций), **динамический** (при выполнении: виртуальные функции) и **параметрический** (при компиляции: шаблоны).
**Абстрактный тип данных (АТД)** — пользовательский тип с полностью скрытой внутренней структурой; в C++ это класс без открытых полей-данных.
**Виды отношений между классами:**
| Отношение | Смысл | Пример |
| Ассоциация | смысловая связь между объектами (один к одному, один ко многим, многие ко многим) | группа — студенты |
| Наследование | класс повторяет и уточняет структуру и поведение базового | `class Z : public Y {…};` |
| Агрегация | «целое / часть»: объект хранит другой объект или указатель на него | дерево хранит `node *root` |
| Композиция | сильная агрегация: объект другого класса — поле класса | `class Z1 { Point p; };` |
| Использование | класс применяет другой класс в параметрах метода, локальных объектах, вызовах | `void f(Point p);` |

## Что такое объектно-ориентированное программирование?
**Ответ из УМКД:** Подход, в котором программа строится из объектов — экземпляров классов, объединяющих данные и методы для работы с ними.
ООП — подход, где программа строится из **объектов**: каждый объект — экземпляр класса, в нём вместе лежат данные и методы для работы с ними. Как в жизни: «кнопка» знает свой текст и умеет нажиматься.

## Основные понятия ООП?
**Ответ из УМКД:** Класс, объект, атрибут (свойство, поле), метод; принципы — инкапсуляция, наследование, полиморфизм, абстракция.
Понятия: **класс** (чертёж), **объект** (вещь по чертежу), **свойство/поле** (характеристика: Caption, Width), **метод** (действие, которое объект умеет: Show, Close), **событие** (сигнал «что-то случилось»: клик — OnClick; это сообщение от ОС программе), **обработчик** (твоя функция-ответ). Четыре принципа: инкапсуляция, наследование, полиморфизм, абстракция.

## Что такое класс?
**Ответ из УМКД:** Набор данных и методов для работы с ними; шаблон (чертёж), по которому создаются объекты с одинаковыми свойствами и поведением.
Класс — набор данных и методов для работы с ними; описание формата данных и доступных функций типа; **шаблон**, по которому создают объекты.

## Что такое объект?
**Ответ из УМКД:** Экземпляр класса в памяти — переменная типа, определённого классом.
Объект — **экземпляр класса в памяти**, переменная типа-класса. Его внутреннее состояние описывают **свойства** (поля).

## Что такое инкапсуляция?
**Ответ из УМКД:** Объединение данных и кода, работающего с ними, в одном объекте и защита данных от произвольного доступа извне (скрытие реализации).
**Инкапсуляция** («в капсулу»): 1) связывает код и данные в одном классе; 2) прячет внутреннее устройство и **защищает данные** от произвольного доступа снаружи (private), наружу — только нужный интерфейс (public). Все тестовые формулировки «links code and data», «protects data», «internal representation hidden» — это инкапсуляция.

## Что такое наследование?
**Ответ из УМКД:** Механизм, при котором производный класс получает свойства и поведение базового и может добавить свои.
**Наследование**: производный класс получает свойства и поведение базового (родительского) и добавляет свои: `class Poodle : public Dog`. Формулировки: «acquires the properties of another object», «using attributes and behavior from pre-existing classes».

## Что такое полиморфизм?
**Ответ из УМКД:** Возможность использовать один интерфейс (одно имя метода) для разных действий; нужный метод выбирается для конкретного объекта.
**Полиморфизм** («много форм»): одно имя / один интерфейс — разные действия у разных классов (`make_sound()` у собаки «Гав», у кошки «Мяу»). В ключе: нужный метод для объекта выбирает **компилятор**.

## Что такое абстракция?
**Ответ из УМКД:** Модель реального предмета, отражающая только важные для задачи свойства и поведение.
**Абстракция** — упрощённая модель реального предмета: берём только важное для задачи (у собаки в программе — кличка и порода, без цвета каждого пятна).

## Чем отличаются инкапсуляция и абстракция?
**Ответ из УМКД:** Абстракция определяет, что показать (существенные свойства), инкапсуляция — прячет детали реализации и защищает данные.
Абстракция решает, **что показать** (существенное), инкапсуляция — **прячет** детали и защищает данные.

## Преимущества объектно-ориентированного подхода?
**Ответ из УМКД:** Близость к реальному миру, повторное использование кода (наследование), защита данных, простота расширения и сопровождения больших программ.
Плюсы ООП: близко к реальному миру, повторное использование кода через наследование, защита данных, проще расширять и сопровождать большие программы.

## Разница между процедурным и объектно-ориентированным подходом?
**Ответ из УМКД:** Процедурный — программа как набор функций над отдельными данными; ООП — набор взаимодействующих объектов, в которых данные и функции объединены.
Процедурный подход — набор функций над отдельными данными. ООП — набор взаимодействующих объектов, в которых данные и функции (методы) объединены.

## Как сущности реального мира представляются объектами и классами?
**Ответ из УМКД:** Общие свойства и действия группы предметов описываются классом (поля и методы), конкретные предметы — объекты этого класса со своими значениями полей.
Общие свойства и действия группы предметов описывает класс (поля и методы), конкретные предметы — объекты со своими значениями полей: класс `Dog`, объекты «Шарик» и «Бобик».

## Определения ООП от преподавателя (под каждым — как это звучит в тесте)

В ООП класс (Class) — это набор данных и методов (methods) для работы с этими данными.

! Как в тесте: In Object-oriented programming, Class is a set of data and methods to manipulate the data.

В ООП класс — это описание формата данных и доступных функций для данного типа.

! Как в тесте: In Object-oriented programming: class is the definitions for the data format and available functions for a given type.

Классы в C++ — это абстракции, описывающие методы и свойства ещё не существующих объектов. Класс — это «чертёж» (blueprint) для создания объектов с похожими атрибутами (attributes) и поведением (behaviors).

! Как в тесте: Classes in C++ are the abstractions that describes methods, properties of objects that do not exist yet. A class is a blueprint for creating objects that have similar attributes and behaviors.

С помощью одного класса можно создать сколько угодно объектов.

! Как в тесте: With the help of one class you can create objects as many as needed.

Класс задаёт свойства (properties) и поведение (behaviors) объектов, а объект — это экземпляр (instance) класса.

! Как в тесте: A class defines the properties and behaviors of objects, whereas an object is an instance of a class.

Объект (Object) — это экземпляр класса в памяти; он создаётся по конкретному классу.

! Как в тесте: Object is an instance of a class in a memory and it is created with the help of concrete class.

Объекты — это экземпляры классов, то есть переменные того типа, который задан классом.

! Как в тесте: Objects are the instances of classes or a variable of the data type defined by the class.

В ООП объект — экземпляр класса в памяти.

! Как в тесте: In OOP, Object is an instance of a class in a memory.

Абстракция (Abstraction) — главный принцип ООП: модель, вид или иное упрощённое представление реального предмета (берём только существенное).

! Как в тесте: Abstraction is the major principle of an OOP that denotes a model, a view, or some other focused representation for an actual item.

Инкапсуляция (Encapsulation) — принцип ООП, механизм, который связывает вместе код и данные, с которыми он работает. Это особый механизм, защищающий данные от произвольного доступа внешнего кода. Инкапсуляция означает, что внутреннее устройство объекта скрыто от всего, что находится вне описания объекта.

! Как в тесте: Encapsulation is a principle of OOP, a mechanism that links together the code and the data it manipulates. Encapsulation is a principle of OOP, a special mechanism that protects data from arbitrary access of other external codes. Encapsulation is the major principle of OOP which means that the internal representation of an object is generally hidden from view outside of the object’s definition.

Инкапсуляция — это скрытие деталей реализации класса и открытие наружу только нужного интерфейса (interface).

! Как в тесте: Encapsulation is the process of hiding the implementation details of a class and only exposing the necessary interfaces to the outside world.

Полиморфизм (Polymorphism) — принцип ООП, механизм, позволяющий использовать один интерфейс для общего класса действий. При полиморфизме выбор нужного метода (для конкретного объекта) выполняет компилятор (compiler). Полиморфизм позволяет использовать одинаковые имена для разной функциональности.

! Как в тесте: Polymorphism is a principle of OOP, a mechanism that allows to use the same interface for a common class of actions. In polymorphism principle: selecting of needed method (for specific object) is performed by compiler. Polymorphism is the major principle of an OOP that allows using same names of identifiers for the different functionality.

Наследование (Inheritance) — принцип ООП, механизм, при котором один объект (производного класса, derived class) получает свойства другого объекта (родителя, базового класса — parent, base class). Наследование позволяет использовать атрибуты и поведение уже существующих классов.

! Как в тесте: Inheritance is a principle of OOP, a mechanism by which one object (of a derived class) acquires the properties of another object (parent, base class). Inheritance is the major principle of an OOP that allows using attributes and behavior from pre-existing classes.

Метод (Method) — специальная функция класса, задающая операции над данными объекта (его поведение). Методы — это действия, которые выполняет компонент (что он умеет).

! Как в тесте: Method is a special function of a class that specifies operations on objects data (specifies its behavior). Methods are the actions performed by the component (what a component can do).

В ООП метод — функция, связанная с классом.

! Как в тесте: In object-oriented programming: method is a function associated with a class.

Метод — действие, которое объект умеет выполнять.

! Как в тесте: Method is an action that an object is able to perform.

Конструктор (Constructor) — специальный метод, который вызывается один раз при создании экземпляра класса. Инициализация всех элементов класса (общая для всех экземпляров) делается в конструкторе.

! Как в тесте: Constructor is a special method that is called once when a class’ instance is created. The initialization of all elements of a class (common for all class instances) is made in constructor.

В ООП свойство (property) — переменная какого-то типа, описывающая внутреннее состояние объекта. Свойства — это атрибуты компонента, определяющие, как он выглядит на экране и как работает.

! Как в тесте: In OOP, property is a variable of some type that characterizes internal status of an object. Properties are the component attributes which determine how a component displayed on the screen and how it operates.

Событие (Event) — сообщение от операционной системы приложению, возникающее при каких-то внешних действиях. Событие — сообщение, возникающее в разных местах выполняемого кода при выполнении определённых условий.

! Как в тесте: OOP: Event is a message from the operating system to an application that if occurs when some external actions are made. Event is a message which occurs at various points in the executable code when certain conditions are performed.

Обработчик события (Event handler) — специальная процедура/функция для реакции на какие-то действия (обычно пользователя).

! Как в тесте: Event handler is a special procedure/function that is used to react at some actions (usually made by user).

Форма (Form) — главный элемент любого приложения; контейнер, в котором находятся все остальные визуальные и невизуальные компоненты.

! Как в тесте: Form is the main element of any application; the container that hosts all other visual and non-visual components.

Object Inspector (инспектор объектов) — часть среды C++ Builder (IDE — среда разработки) для просмотра и изменения свойств и событий выбранного объекта. Свойства компонента задаются в Object Inspector.

! Как в тесте: Object Inspector is a part of C++ Builder IDE that is used to examine and edit the properties and events for the currently selected object. A component’s properties are set in Object Inspector

Code Editor (редактор кода) — часть среды C++ Builder, где хранится набор команд программы.

! Как в тесте: Code Editor is a part of a C++ Builder IDE that holds the set of a program commands.

Компоненты (Components) — самостоятельные «кирпичики», которые кладут на форму, чтобы собрать приложение.

! Как в тесте: Components are the self-contained building blocks that are carried on the form to create your applications.

Компоненты, которые выглядят одинаково при проектировании (design stage) и во время работы программы, называются визуальными (Visual components). Их ещё называют элементами управления (Controls).

! Как в тесте: The components that look the same at the design stage and during the application execution are called the Visual components. Visual components are also called Controls.

Компоненты, невидимые во время работы программы, называются невизуальными (Non-visual).

! Как в тесте: The components that invisible during the application execution are called Non-visual.

Четыре парадигмы программирования:

Процессно-ориентированная (процедурная, императивная) — программа есть последовательность операций, код воздействует на данные (модель фон Неймана). Языки C, Pascal.
Объектно-ориентированная — программа есть набор объектов, которые общаются через интерфейсы; данные управляют доступом к коду.
Аппликативная (функциональная) — программа есть функция y = f(x), собранная из простых функций. LISP, ML; применяют в системах искусственного интеллекта.
Логическая (система правил) — список пар «разрешающее условие → действие», условия проверяются по кругу. PROLOG.

Центральная идея ООП — абстракция: сложную сущность рассматривают как единое целое, не вдаваясь во внутреннее устройство. Главный способ строить абстракции — иерархическая классификация: сложную систему делят на более простые части. Различают структуру классов (типовая иерархия) и структуру объектов (структурная иерархия).

Инкапсуляция — связывает код и данные, которыми он управляет, и защищает их от произвольного доступа извне; доступ идёт через интерфейс. Основа инкапсуляции — класс.
Наследование — объект производного класса получает свойства родительского (базового) класса и добавляет только то, что делает его особенным.
Полиморфизм — «один интерфейс — много методов»: например, одна подпрограмма для стеков целых, вещественных чисел и символов. Бывает статический (при компиляции: перегрузка функций и операций), динамический (при выполнении: виртуальные функции) и параметрический (при компиляции: шаблоны).

Абстрактный тип данных (АТД) — пользовательский тип с полностью скрытой внутренней структурой; в C++ это класс без открытых полей-данных.

Виды отношений между классами:

| Отношение | Смысл | Пример |
| Ассоциация | смысловая связь между объектами (один к одному, один ко многим, многие ко многим) | группа — студенты |
| Наследование | класс повторяет и уточняет структуру и поведение базового | class Z : public Y {…}; |
| Агрегация | «целое / часть»: объект хранит другой объект или указатель на него | дерево хранит node *root |
| Композиция | сильная агрегация: объект другого класса — поле класса | class Z1 { Point p; }; |
| Использование | класс применяет другой класс в параметрах метода, локальных объектах, вызовах | void f(Point p); |
