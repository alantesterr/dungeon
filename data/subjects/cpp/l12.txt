## 1. Наследование
**База и наследник**
```
class Animal                       // базовый (родительский) класс
{
protected:
  string name;                     // видно в наследниках
public:
  Animal(string n) : name(n) {}
  void eat() { cout << name << " ест" << endl; }
};
class Dog : public Animal          // производный (дочерний) класс
{
public:
  Dog(string n) : Animal(n) {}     // вызов конструктора базового класса
  void bark() { cout << name << ": Гав" << endl; }
};
```
Иерархия классов — дерево: базовый класс наверху, наследники ниже, у наследника могут быть свои наследники.
Наследник получает все поля и методы базового и добавляет свои — повторное использование кода.
Одиночное наследование — один базовый класс; множественное — несколько: class Amphibian : public Car, public Boat.
Порядок: при создании объекта сначала работает конструктор базового класса, потом наследника; деструкторы — в обратном порядке.

! Вопрос УМКД: **Что такое иерархия классов?** — Система классов, связанных наследованием: базовые классы наверху, производные — ниже (дерево).
! Вопрос УМКД: **Что такое наследование?** — Механизм создания нового класса на основе существующего: производный класс получает свойства и методы базового и добавляет свои.
! Вопрос УМКД: **Что такое базовый класс?** — Класс, от которого наследуют (родительский).
! Вопрос УМКД: **Что такое производный класс?** — Класс, созданный наследованием от базового (дочерний): class Dog : public Animal.
! Вопрос УМКД: **Преимущества наследования?** — Повторное использование кода, меньше дублирования, логичная структура, расширение без изменения базового класса, полиморфизм.
! Вопрос УМКД: **Что такое одиночное наследование?** — У класса один базовый класс.
! Вопрос УМКД: **Что такое множественное наследование?** — У класса несколько базовых классов: class C : public A, public B.

## 2. Доступ при наследовании
**Public / protected / private**
| Член базового | public-наследование | protected-наследование | private-наследование |
| public | public | protected | private |
| protected | protected | protected | private |
| private | недоступен | недоступен | недоступен |

private-члены базового класса существуют в наследнике, но обращаться к ним напрямую он не может — только через методы базового. Обычно используют public-наследование.

! Вопрос УМКД: **Как наследование влияет на public, protected и private?** — private базового недоступны наследнику; protected доступны в наследнике, но не снаружи; при public-наследовании public остаются public; при private-наследовании всё становится private.

## 3. Переопределение и виртуальные функции
**Virtual и полиморфизм**
Переопределение (overriding) — в наследнике метод с тем же именем и параметрами, что в базовом.
Виртуальный метод (virtual) — при вызове через указатель или ссылку на базовый класс вызывается версия настоящего класса объекта. Без virtual — версия базового класса (по типу указателя).
Чисто виртуальный метод virtual double area() = 0; — без реализации; класс с ним абстрактный: создать его объект нельзя, только наследников.
Связь с полиморфизмом: наследование + virtual позволяют обрабатывать разные объекты одним кодом через указатели на базовый класс.
Если класс используется полиморфно, его деструктор делают virtual, чтобы delete через указатель на базовый вызвал деструктор наследника.

! Вопрос УМКД: **Что такое переопределение метода?** — Определение в производном классе метода с той же сигнатурой, что в базовом, чтобы изменить его поведение.
! Вопрос УМКД: **Что такое виртуальный метод?** — Метод, объявленный virtual; при вызове через указатель/ссылку на базовый класс вызывается версия настоящего класса объекта.
! Вопрос УМКД: **Как наследование связано с полиморфизмом?** — Наследники переопределяют виртуальные методы базового, и через указатель на базовый класс одним кодом обрабатываются объекты разных классов.

## 4. Иерархия классов VCL в C++Builder
**TObject и его наследники**
```
TObject                    — корень: создание/удаление объектов, информация о типе (RTTI), ClassName()
 └ TPersistent             — умеет сохранять свойства (в файл формы .dfm)
    └ TComponent           — компонент: Name, Owner, Tag; можно положить на форму
       ├ TTimer, TOpenDialog, TMainMenu …   невизуальные компоненты
       └ TControl          — видимый элемент: Left, Top, Width, Height, Visible, Caption, OnClick
          ├ TGraphicControl — без своего окна: TLabel, TImage, TShape, TSpeedButton
          └ TWinControl     — с окном Windows, может получать фокус и содержать другие
             ├ TButton, TCheckBox, TRadioButton (через TButtonControl)
             ├ TEdit, TMemo (через TCustomEdit)
             ├ TListBox, TComboBox
             ├ TPanel, TGroupBox — контейнеры
             └ TForm (через TScrollingWinControl → TCustomForm)
```
TObject — базовый класс всех классов VCL: даёт создание и уничтожение объектов (Create/Free, управление памятью) и информацию о типе во время работы (ClassName, ClassParent).

Контейнеры (TPanel, TGroupBox, TPageControl, сама форма) — компоненты, на которых лежат другие: дочерние компоненты двигаются вместе с контейнером, их координаты отсчитываются от него, Visible/Enabled контейнера действуют на всех детей. Свойство Parent у компонента — его контейнер. Создать компонент в программе: TButton *b = new TButton(this); b->Parent = Panel1;, удалить — delete b;.

! Вопрос УМКД: **Как представить иерархию классов в программе?** — Описать базовый класс и производные с указанием базового (class B : public A), при необходимости — virtual-методы; в C++Builder — иерархия VCL от TObject.

## Формулировки из теста (англ. — с переводом)

protected — поле или метод видит сам класс и все классы-наследники (the class itself and any classes derived from it). private — только сам класс. public — любой код.

Корень дерева классов VCL (The root of the VCL class hierarchy tree):

TObject
```

    ├ TGraphic   ├ TGraphicObject   ├ TCanvas   ├ TPicture   ├ TStrings
```

| TObject | общие элементы (поведение) всех объектов VCL. Если при создании класса базовый класс не указан, предком автоматически становится TObject. |

| TControl | базовый класс всех элементов управления (controls), включая окно формы; видимы во время работы. Даёт положение, подсказку (hint), рисование и перемещение, события мыши. |

| TScreen | глобальная переменная Screen; доступа из Object Inspector нет. Даёт сведения об экране: разрешение, курсоры, шрифты, список форм и активная форма. |
| TForm | базовый класс окна-формы; каждая новая форма — наследник TForm (class TForm1 : public TForm). Форма бывает: главным окном приложения, диалоговым окном, дочерним окном MDI. |
| TMainMenu | строка меню формы и выпадающие меню. |
| TMenuItem | пункт меню; его контейнер — TMainMenu или TPopupMenu. |
| TPopupMenu | контекстное (всплывающее) меню по правой кнопке мыши; базовый класс — TMenu. |

Parent и Owner. Родитель (parent) — компонент, на котором непосредственно лежит компонент. Владелец (owner) всех компонентов формы — сама форма; владелец всех форм — приложение (Application). Если компонент лежит не прямо на форме, а, например, на TPanel, то родитель (панель) и владелец (форма) — разные компоненты.

Свойства TComponent:

ComponentCount — сколько компонентов принадлежит этому компоненту;
ComponentIndex — номер компонента в массиве Components его владельца (первый — 0);
Components — список всех принадлежащих компонентов: обращение по номеру или перебор в цикле;
Name — имя компонента в коде; Builder даёт его сам по имени класса (Button1, Edit1…);
Owner — владелец. Компонент всегда удаляется (память освобождается), когда удаляется его владелец.
```
for (int i = 0; i < ComponentCount; i++)          // все компоненты формы
  if (TEdit *e = dynamic_cast<TEdit*>(Components[i]))
    e->Text = "";                                   // очистить все Edit
```
Свойства TControl:

| Свойство | Смысл |
| Action | действие (action), связанное с элементом |
| AutoSize | менять ли размер автоматически при изменении содержимого |
| Caption | строка-заголовок окна или надпись. Знак & подчёркивает следующую букву — это клавиша-ускоритель: Alt + буква переносит фокус на элемент. Caption = "&Open" → Open |
| Color, ParentColor | цвет фона; если ParentColor = true, фон меняется вместе с фоном родителя |

| HelpType | как задаётся тема справки: htContext → номер в HelpContext, htKeyword → слово в HelpKeyword |

| PopupMenu | контекстное меню элемента. Если у TPopupMenu AutoPopup = true, меню появляется само; если false — его вызывают методом Popup в обработчике OnContextPopup |

Методы TControl: Click — вызывает событие OnClick (Label1->Click();); Create — создаёт экземпляр и задаёт свойства; DblClick — вызывает OnDblClick; Hide — прячет (Visible = false): Button1->Visible = false; то же, что Button1->Hide();; Refresh — перерисовывает элемент, вызывая Repaint; Show — делает видимым (Visible = true).

Свойства TWinControl: ControlCount — число дочерних элементов; Controls — список дочерних элементов; TabOrder — номер элемента в порядке обхода клавишей Tab внутри родителя.

Свойства TApplication: HelpFile — файл справки; Icon — значок в заголовке рядом с именем приложения; MainForm — главная форма: когда она закрывается, закрывается и приложение; ShowMainForm — по умолчанию true: главное окно показывается при запуске (чтобы скрыть его, в Project1.cpp до Application->Run() пишут Application->ShowMainForm = false; и у главной формы Visible = false); Title — заголовок приложения.

Свойства TForm: Active — активна ли форма; ActiveControl — элемент с фокусом ввода; ActiveMDIChild — активное дочернее MDI-окно; BorderStyle — вид и поведение рамки; FormStyle:

fsNormal — обычная SDI-форма (не дочернее и не родительское MDI-окно);
fsMDIChild — дочернее MDI-окно;
fsMDIForm — родительское MDI-окно;
fsStayOnTop — «всегда сверху» над формами проекта без этого стиля.

Ещё: HelpFile; Icon — значок в заголовке окна; MDIChildCount — число открытых дочерних MDI-форм; MDIChildren — их список; Menu / PopupMenu — главное и контекстное меню; Parent — у формы без родителя равен nil (NULL); Position — размер и положение при первом показе; WindowState — свёрнута, развёрнута на весь экран или обычная.

Методы TForm (для MDI): Cascade — расставить дочерние окна каскадом; Next / Previous — сделать активным следующее / предыдущее дочернее окно; Tile — расставить дочерние окна одинакового размера мозаикой на всю клиентскую область. Класс формы — контейнер для всех компонентов на ней.

TMainMenu. Меню формы создают в три шага: 1) положить на форму компонент TMainMenu; 2) двойной щелчок по нему — в редакторе меню вписать заголовки пунктов строки меню и выпадающих меню; 3) написать обработчик события для каждого пункта. Свойства: AutoMerge — можно ли сливать меню (как именно — зависит от GroupIndex пунктов); Handle — дескриптор меню для функций Windows API.

TMenuItem. При создании меню в дизайнере для каждой команды автоматически создаётся объект TMenuItem. Свойства:

Action — связанное действие. По умолчанию у пункта событие OnClick, имя обработчика строится из имени формы и пункта (TForm1::Item12Click); одно «действие» можно использовать для разных объектов;
AutoHotkeys — назначать ли клавиши-ускорители подпунктам автоматически;
Bitmap — картинка слева от заголовка; Break — начать ли с пункта новый столбец меню;
Caption — текст пункта; буква после & — ускоритель (Alt + буква);
Checked — пункт как флажок (галочка слева); Default — пункт по умолчанию (выполняется по двойному щелчку на родительском подменю, выделен жирным); Enabled — доступен ли;
HelpContext, Hint — справка и подсказка; ImageIndex — номер картинки из списка Images родителя;
Items — подпункты; MenuIndex — номер пункта в родительском меню; Parent — родительское меню; Visible — виден ли.

Методы TMenuItem: Add — добавить пункт(ы) в конец Items; Clear — удалить все подпункты; Click — вызвать OnClick; Create — создать пункт; Delete — удалить пункт с номером; IndexOf — номер пункта в Items; Insert — вставить пункт.

Общее «действие» для пункта меню и кнопки: положить на форму TActionList → двойной щелчок → в редакторе добавить действие (TAction) → двойной щелчок по нему откроет код обработчика → у пункта меню выбрать это действие в свойстве Action.

## Из учебника МГУ (волкова, иванов, карпов) · наследование глубже
Что не наследуется: конструкторы, деструктор, операция присваивания. Конструктор базового класса с параметрами вызывают только в списке инициализации: Dog(string n) : Animal(n) {}.
Объекту базового типа можно присвоить объект наследника — скопируется только «базовая часть». Указатель на наследника безопасно превращается в указатель на базовый (A *pa = pb;); обратно — только явно и небезопасно: pb = (B*)pa;.
Если тип наследования не указан: у class — private, у struct — public.
Перекрытие имён: метод наследника с тем же именем закрывает метод базового, но тот остаётся доступен через квалификатор: A::f(1); или pc->A::f(1);. Без virtual вызов через указатель решает тип указателя.
Виртуальные функции: вызов через указатель/ссылку решает тип объекта (динамический полиморфизм). Класс хотя бы с одной virtual-функцией — полиморфный. Реализация — таблица виртуальных методов (ТВМ, VMT): в каждом полиморфном объекте есть скрытый указатель на таблицу адресов виртуальных методов его класса; в таблице наследника адреса переопределённых методов заменены, новые дописаны в конец.
Виртуальный деструктор: A *p = new C; delete p; — без virtual ~A() вызовется только ~A(), и память наследника не освободится; с virtual — сначала ~C(), потом ~A(). Конструктор виртуальным быть не может.
Абстрактный класс — есть хотя бы одна чистая виртуальная функция virtual void f() = 0;. Объекты создавать нельзя, указатели — можно. Интерфейс — абстрактный класс без полей, только с открытыми чистыми виртуальными функциями.
Множественное наследование: class Z : public X, public Y. Одинаковые имена в X и Y дают неоднозначность — пишут z1.X::i1 = 5;. Если X и Y унаследованы от общего W и нужен один экземпляр W — виртуальное наследование: class X : public virtual W.
RTTI: dynamic_cast<B*>(p) — безопасное приведение в иерархии (вернёт NULL, если объект не того типа; для ссылки — исключение bad_cast); typeid(x).name() — имя типа.
**Формулировки из теста (англ. — с переводом)**
Если базовый класс не указан, предок — TObject (the ancestor is TObject).
Предок всех компонентов VCL — TComponent; базовый класс всех элементов управления (controls) — TControl; всех оконных элементов (window controls) — TWinControl; базовый класс окна-формы — TForm.
Владелец (owner) всех компонентов на форме — сама форма; владелец всех форм — приложение (the application).
Компонент всегда удаляется вместе со своим владельцем (when its owner is deleted).
Знак & в Caption — следующая буква подчёркивается и становится «горячей клавишей» (accelerator key): Alt + эта буква.
fsStayOnTop — форма всегда поверх других окон; fsMDIChild — дочернее MDI-окно; fsMDIForm — родительское MDI-окно.
Базовый класс TPopupMenu — TMenu; всплывающее меню появляется само, если AutoPopup = True.
