## Проект и форма

Создание проекта: File → New → Application. Builder сразу создаёт пустую форму Form1 и модуль Unit1. Сохранять лучше в отдельную папку: File → Save All — сначала спросит имя Unit1.cpp, потом Project1.bpr.

| Файл | Что внутри |
| Project1.bpr | настройки проекта |
| Project1.cpp | главная функция WinMain: создаёт формы и запускает приложение (Application->Run()) |
| Unit1.cpp | код формы — обработчики событий |
| Unit1.h | объявление класса TForm1: компоненты и обработчики (Builder пишет сам) |
| Unit1.dfm | описание вида формы: какие компоненты, где лежат, их свойства |
| Project1.res | ресурсы: значок программы |

Форма (Form) — главный элемент любого приложения: окно, контейнер, на котором размещаются все визуальные и невизуальные компоненты. Каждая форма — объект класса TForm1, наследника TForm. Пользователь работает с программой через формы — это и есть графический интерфейс пользователя (GUI): окна, кнопки, поля, меню, которыми управляют мышью и клавиатурой.

! Вопрос УМКД: **Что такое проект в C++Builder?** — Совокупность файлов одной программы (.bpr, Project1.cpp, Unit1.cpp/.h/.dfm, .res), из которых собирается exe.
! Вопрос УМКД: **Основные шаги создания нового проекта?** — File → New → Application; разместить компоненты на форме; настроить свойства; написать обработчики; File → Save All; F9.
! Вопрос УМКД: **Что такое форма?** — Окно приложения, главный элемент и контейнер для визуальных и невизуальных компонентов; объект класса-наследника TForm.
! Вопрос УМКД: **Назначение формы в визуальном приложении?** — Быть интерфейсом программы: через форму и её компоненты пользователь вводит данные и получает результат.
! Вопрос УМКД: **Что такое графический интерфейс пользователя?** — Окна, кнопки, поля ввода, меню и другие элементы, через которые пользователь управляет программой мышью и клавиатурой.

## Дизайнер форм
Добавить компонент: щёлкнуть его на палитре, затем по форме (или двойной щелчок на палитре — компонент встанет в центр).
Переместить — перетащить мышью или стрелками с Ctrl; размер — потянуть за чёрные квадратики (или Shift+стрелки). Точная настройка — свойствами Left, Top, Width, Height в Object Inspector.
Выравнивание: выделить несколько компонентов (Shift+щелчок) → правая кнопка → Align (по левому краю, по центру…), Size (одинаковый размер). Свойство Align прижимает компонент к краю родителя (alTop, alBottom, alLeft, alRight, alClient — заполнить всё).
Связь формы с кодом: каждый компонент — поле класса формы (TButton *Button1; в Unit1.h). Двойной щелчок по компоненту создаёт обработчик его главного события в Unit1.cpp. Свойства можно менять и в Object Inspector (при проектировании), и в коде (во время работы).
Этапы создания простого приложения: 1) новый проект; 2) разместить компоненты; 3) настроить свойства; 4) написать обработчики событий; 5) сохранить; 6) запустить и проверить (F9).
Несколько форм: File → New → Form добавляет Form2; в Unit1.cpp подключить #include "Unit2.h"; открыть — Form2->Show(); (можно работать с обеими) или Form2->ShowModal(); (пока Form2 открыта, первая недоступна); закрыть — Close();. Без стандартного метода: Form2->Visible = true;

! Вопрос УМКД: **Что такое дизайнер форм?** — Режим/окно IDE, в котором мышью размещают и настраивают компоненты на форме.
! Вопрос УМКД: **Как добавить компоненты на форму?** — Выбрать компонент на палитре компонентов и щёлкнуть по форме (или дважды щёлкнуть по значку на палитре).
! Вопрос УМКД: **Как менять положение и размер компонента?** — Перетаскиванием мышью и маркерами размера или свойствами Left, Top, Width, Height в Object Inspector; Align — прижать к краю.
! Вопрос УМКД: **Основные этапы создания простого визуального приложения?** — Создать проект → разработать форму (компоненты) → задать свойства → написать обработчики событий → сохранить → запустить и проверить.

## Форма и таймер (для теста)
Form (форма) — the main element of any application; the container that hosts all other visual and non-visual components (главный элемент приложения, контейнер для всех компонентов).
Timer (вкладка System) — to periodically perform certain actions (периодически выполнять действия). Единственное событие — OnTimer. Interval = 1000 — раз в секунду (в миллисекундах). Enabled = false — таймер остановлен.
Запретить менять размер окна: BorderStyle = bsDialog (или bsSingle). Из кода Width всё равно можно менять: при bsSingle ширина изменится, но мышкой её поменять нельзя.
WindowState: wsNormal (обычное), wsMaximized (на весь экран), wsMinimized. Вернуть развёрнутую форму: Form1->WindowState = wsNormal;
Align: alBottom — компонент прижат к низу и растянут по ширине родителя (высота своя); alTop, alLeft, alRight, alClient — на всё свободное место.
Anchors (якоря): чтобы компонент растягивался вместе с формой по горизонтали и вертикали — [akLeft, akTop, akRight, akBottom].
OnResize — сразу после изменения размера формы или панели.

## Файл Unit1.h — класс формы
```
#ifndef Unit1H                 // «подключить один раз» (в новых версиях — #pragma once)
#define Unit1H
#include <Classes.hpp>
#include <Controls.hpp>
#include <StdCtrls.hpp>          // TEdit, TButton, TLabel, TMemo (в новых версиях — VCL.StdCtrls.hpp)
#include <Forms.hpp>             // TForm (в новых версиях — VCL.Forms.hpp)
class TForm1 : public TForm      // класс формы: ключевое слово class, наследник TForm, имя с буквы T
{
__published:   // IDE-managed Components — сюда IDE сама пишет компоненты с формы
        TButton *Button1;        // компонент — это УКАЗАТЕЛЬ на объект класса
        TEdit *Edit1;
        void __fastcall Button1Click(TObject *Sender);   // обработчик: void __fastcall, параметр TObject *Sender
private:       // User declarations — свои поля и вспомогательные методы только для этой формы
        int counter;
public:        // User declarations — то, что можно вызывать снаружи (из других форм)
        __fastcall TForm1(TComponent* Owner);   // конструктор: обязательный параметр TComponent* Owner
};
extern PACKAGE TForm1 *Form1;    // extern: переменная Form1 определена в Unit1.cpp и видна в других файлах
#endif
```
| Секция | Кто видит |
| __published | как public + видно в Object Inspector. Здесь компоненты с формы и обработчики событий. |
| private | только сама форма (свои вспомогательные методы и поля). |
| protected | сама форма и классы-наследники (derived classes). |
| public | все: конструктор, методы для вызова из других форм. |
__fastcall — соглашение о вызове, обязательное для обработчиков VCL. Деструктор: __fastcall ~TForm1();
Sender — компонент, который вызвал событие.
Методы объявляют в .h, чтобы компилятор знал их заголовок (signature) и видимость, а код пишут в .cpp.
Объявление обработчика вручную — бери точно тот заголовок, который создаёт IDE двойным щелчком в Object Inspector.
Если удалить из .h строку TEdit *Edit1;, компиляция не пройдёт: в Builder 6 будет ошибка Undefined symbol 'Edit1' (в новых — Undeclared identifier).
__property — своё свойство класса с чтением/записью закрытого поля (тема 14).
В тестах встречается FireMonkey (FMX) — другая библиотека новых версий C++Builder (там форма — TForm из FMX, свойства Fill->Color, Opacity). В Builder 6 её нет.

Цель занятия — описать файлы, из которых состоит проект, и окно, в котором редактируют формы программы.

1. Создание проекта. Первый шаг — создать проект (project). Файлы проекта содержат автоматически сгенерированный код (automatically generated source code), который становится частью программы при компиляции.

Borland C++Builder 6: File → New → Application
Если уже открыт другой проект, сначала File → Close All, иначе имена файлов проектов могут конфликтовать.
! Как в тесте: Embarcadero C++Builder: File → New → VCL Forms Application

2. Файл проекта Project1.cpp. Builder сам создаёт файл с именем по умолчанию Project1.cpp и сам его меняет, когда ты меняешь проект (например, добавляешь форму).

```
#include <vcl.h>
#pragma hdrstop
//---------------------------------------------------------------------------
USEFORM("Unit1.cpp", Form1);      // форма Form1 и модуль Unit1.cpp, где её обработчики
USEFORM("Unit2.cpp", Form2);
//---------------------------------------------------------------------------
WINAPI WinMain(HINSTANCE, HINSTANCE, LPSTR, int)
{
    try
    {
        Application->Initialize();
        Application->CreateForm(__classid(TForm1), &Form1);   // первая созданная = главная форма
        Application->CreateForm(__classid(TForm2), &Form2);
        Application->Run();                                   // запуск цикла сообщений
    }
    catch (Exception &exception)
    {
        Application->ShowException(&exception);
    }
    return 0;
}
```
USEFORM("Unit2.cpp", Form2); — называет форму проекта и модуль (файл), в котором лежат все её обработчики событий, функции и т. д.
#include "Unit2.h" — подключает заголовок, где описаны прототипы обработчиков и функций, а также глобальные идентификаторы.

3. Работа с формами. Дизайнер форм. Главный элемент любого приложения — форма: a container which other visual and non-visual components are placed in (контейнер для визуальных и невизуальных компонентов). В проекте может быть несколько форм. У каждой новой формы свой модуль (unit): в нём форма описана как класс, а также, если нужно, константы, переменные, функции и процедуры.

Добавить форму: File → New → Form. Появятся форма и модуль: Unit2.cpp, Unit2.h, Unit2.dfm.
Быстро переключаться между формами — кнопка View Form (Shift+F12): откроется список форм «Form1 (Unit1.cpp), Form2 (Unit2.cpp)». Между модулями — View Unit (Ctrl+F12), форма ↔ код — F12.
! Как в тесте: В Project Manager видно дерево: Project1.exe → Project1.cpp, Project1.res, Unit1.cpp (Unit1.cpp, Unit1.dfm, Unit1.h), Unit2.cpp (…).

4. Главная форма. В проекте может быть только одна главная форма (only one main form):

по умолчанию главная — форма, созданная первой;
приложение начинается с главной формы — пользователь видит её первой;
если закрыть главную форму, закроется всё приложение;
назначить другую главную форму: Project → Options → Forms, список Main form.

В окне Project Options → Forms два списка:

Auto-create forms — формы, которые будут созданы в памяти автоматически при запуске (видимые они или нет — не важно).
Available forms — формы, которые автоматически не создаются, но доступны проекту. Такую форму надо создать в памяти вручную:
```
Application->CreateForm(__classid(TForm2), &Form2);   // создать в памяти
Form2->Show();                                          // показать на экране
```
Пока форма не создана, Form2 = NULL, и Form2->Show() даст ошибку Access violation.

5. Связь форм. Как бы форма ни была создана (автоматически или динамически), чтобы работать с ней из другой формы, нужно подключить её заголовок *.h к той форме, откуда её вызывают:

```
#include <vcl.h>
#pragma hdrstop
#include "Unit2.h"   // модуль главной формы
#include "Unit1.h"   // модуль подключаемой (зависимой) формы
//---------------------------------------------------------------------------
#pragma package(smart_init)
#pragma resource "*.dfm"
TForm2 *Form2;
```
В C++Builder 6 строку #include вставляет команда File → Include Unit Hdr… (Alt+F11). Без неё компилятор скажет [C++ Error] Unit1.cpp: E2451 Undefined symbol 'Form2'.

! Вопрос УМКД: **Связь формы и программного кода?** — Компоненты формы — поля класса TForm1 (Unit1.h), события компонентов связаны с методами-обработчиками в Unit1.cpp; вид формы хранится в Unit1.dfm.

## Show, ShowModal, Close, Hide
| Код | Что делает |
| Form2->Show(); | показать форму; можно дальше работать с обеими (немодальная) |
| Form2->ShowModal(); | показать модально: пока Form2 не закрыта, Form1 недоступна; возвращает ModalResult (mrOk, mrCancel…) |
| Form2->Hide(); / Visible = false | спрятать форму (в памяти она остаётся) |
| Close(); | закрыть текущую форму; если это главная — закрывается всё приложение |
| ModalResult = mrOk; | в модальной форме: закрыть её и вернуть mrOk в ShowModal. То же делает кнопка со свойством ModalResult = mrOk |
```
void __fastcall TForm1::Button1Click(TObject *Sender)
{
  if (Form2->ShowModal() == mrOk)           // ждём, пока Form2 закроют
    Label1->Caption = Form2->Edit1->Text;    // берём то, что ввели на Form2
}
```
Всё это можно попробовать во вкладке C++Builder (после темы 15): там есть File → New → Form, Project → Options → Forms и запуск нескольких форм.

**Формулировки из теста (англ. — с переводом)**
Первый шаг в разработке приложения C++Builder — создать проект (to create a project).
Файлы проекта содержат автоматически созданный исходный код (automatically generated source code).
Имя файла проекта по умолчанию — Project1.cpp.
USEFORM("Unit2.cpp", Form2) указывает имя формы проекта и модуль, в котором лежат её обработчики событий (the name of the project's form and the unit in which its event handlers are located).
Сколько главных форм может быть в проекте? — Только одна (only one); по умолчанию главная — форма, созданная первой.
Формы, которые создаются в памяти автоматически, — Auto-create forms; формы, которые сами не создаются, но доступны, — Available forms.
Назначить другую главную форму — Project → Options → Forms. Переключаться между формами — View Form (Shift+F12).
