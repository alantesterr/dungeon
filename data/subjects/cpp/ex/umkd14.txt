<tr>(УМКД) Почему данные класса обычно инкапсулируют?</tr>

<variant> to make the program faster <tr>чтобы программа работала быстрее</tr>

<variant> to save memory <tr>чтобы сэкономить память</tr>

Ответ: через setter нельзя записать возраст −5, а внутреннее устройство класса можно менять, не ломая остальную программу.
Ловушка: public-поля не запрещены, просто ими легко испортить данные.
По лекции: тема 14, раздел «Свойство, get и set».</explain>

<question> (УМКД) What does a getter do?

<question> (УМКД) How is a read-only property made?
<tr>(УМКД) Как сделать свойство только для чтения?</tr>
<variantright> provide a getter (read) but no setter (write) <tr>дать getter (read), но не делать setter (write)</tr>

<question> (УМКД) What is the difference between a public data member and an encapsulated property?
<tr>(УМКД) Чем public-поле отличается от инкапсулированного свойства?</tr>
<variantright> a public field can be changed to any value directly; an encapsulated property only through methods that check the value <tr>public-поле можно напрямую поменять на любое значение, инкапсулированное свойство — только через проверяющие методы</tr>
<variant> there is no difference <tr>никакой разницы</tr>
<variant> a public field cannot be read <tr>public-поле нельзя прочитать</tr>
<variant> an encapsulated property cannot be changed at all <tr>инкапсулированное свойство нельзя изменить вообще</tr>
<explain>Вопрос по УМКД (добавлен к базе).
Ответ: p.age = -5; с public-полем пройдёт, а p.setAge(-5) значение отклонит.
По лекции: тема 14, раздел «Свойство, get и set».</explain>

<question> (УМКД) In __property int Age = {read = FAge, write = SetAge}; what happens on p.Age = 20; ?

<variantright> the method SetAge(20) is called <tr>вызывается метод SetAge(20)</tr>
<variant> the field FAge is read <tr>читается поле FAge</tr>

<variant> a new object is created <tr>создаётся новый объект</tr>

По лекции: тема 14, раздел «Свойства в C++Builder: __property».</explain>
